# 半山学堂研究生教学案例库设计规格

> 状态：待用户审阅。此规格确认前不进入代码实施。

## 目标

在半山学堂现有栏目中建立可检索、可维护、按授权分级展示的研究生教学案例库。建设规范中的案例正文、教学指导手册、附件、审核与版本、使用登记构成网站数据结构和页面的依据。

## 来源与事实边界

- 依据知识库只读资料 `研究生教学案例库模板包/01_研究生课程教学案例库建设规范.docx` 及配套 Markdown、正文模板、指导手册模板、台账 Excel。
- 案例按课程/模块组织；支持教学型、研究型、小微、视频、短视频类型。
- 元数据包含编号、标题、类型、课程与模块、适用对象、知识点/指标点、学时/形式、来源、作者贡献、审核、入库日期/版本、授权/保密、查重、字数/附件、使用记录、关键词、关联案例。
- 教学型案例需有配套指导手册；公开或受限资源必须符合授权和保密状态。案例版本应保留，入库后两年复审；每次课堂使用可登记班级、教师、形式、学时、人数、满意度、反馈和改进建议。
- 模板包没有已登记案例内容；台账“案例总表”为空。首期只建功能与录入能力，不自动把模板、种子文章或未经核实的历史材料当作正式案例发布。
- 原始知识库资料保持只读；本规格与实现仅写入当前部署仓库。

## 现有系统基线

- 半山学堂前端为 Vue 3；后端为 Express/TypeScript/MySQL。
- 目前文章数据只有分类、标题、摘要、Markdown 正文、普通标签、作者、精选和发布状态。
- `admins` 是唯一账号表；现有 JWT 不含角色；`/uploads` 当前作为公开静态目录提供服务。
- `method` 分类和 `/section/method` 已承担改名后的栏目入口。该 URL 应保留，旧 `/article/:id` 文章链接继续可访问。

## 推荐方案

新增独立案例模块，与现有文章系统并存。案例和案例版本、分类标签、附件、审核记录、使用登记分别管理；不把案例塞进普通文章 Markdown 或逗号分隔标签字段。将 `/section/method` 作为案例库首页入口，导航显示“教学案例库”；案例详情使用稳定案例编号路由。既有文章记录不删除、不自动迁移，案例库只查询专用案例表。

### 公开页面

1. **案例库首页**：栏目导语说明服务对象、内容范围和使用方式；重点案例明确标记为编辑精选，不暗示是全部案例；按课程、年级进入具体课题；提供方法/主题标签（如材料转译、图形表达、文字设计、传统文化、社会议题）、关键词检索、最新更新与更新时间；说明学生作品展示、教师手册权限、引用和授权边界，并有清晰空状态。
2. **案例详情页**：路由为 `/cases/:caseCode`；展示标题和课程/年级/课题/时间/方法标签/公开状态等基本信息；案例导读、课题任务与问题、作业全览（逐项可展开）、综合分析与教学启示；每件作品记录展示授权状态、过程材料、媒介和作者自述，未获展示授权的作品不公开；教师区列教学目标与准备、教学流程、讨论问题与课堂活动、评价建议及教学指导手册下载，需教师登录/授权；页面底部列来源、作者署名、版权与引用方式、相关案例。教学型正文还须满足模板要求的章节和篇幅，不把空模板提示当作正文内容。
3. **公开准入**：只有管理员标记审核通过、授权状态允许公开且已发布的当前版本进入公开列表和详情接口。仅校内、仅课堂使用或授权未核实的案例不出现在公开 API；具体受限材料不由公开静态文件路径提供。

### 教师与后台

- 在现有账号认证基础上增加 `admin`、`teacher` 角色。保留现有管理员为 admin；不开放自助注册。管理员可创建、停用教师账号。
- 教师登录后可读取被授权的教师指导手册和教师级附件，并登记课堂使用记录；教师不能编辑、审核或发布案例。管理员负责案例编辑、提交/审核状态、授权状态、附件、版本、复审和教师账号。
- 指导手册、授权凭证、查重报告及仅校内/课堂附件存于非公开文件目录，通过鉴权 API 下载；不可放在现有公开 `/uploads` 静态根目录。
- 管理界面覆盖模板台账的元数据、版本、授权/审核、附件和使用登记。审核记录支持登记至少两名匿名同行专家的结论；仅审核通过的版本可发布。复审到期提示基于最近入库/复审日期计算。
- 教师指导手册表单覆盖适用对象与先修要求、知识/能力/素养目标、分层问题与参考思路、分析框架、课前准备、课堂时间安排与讨论组织、常见误区、带权重的评价量表、推荐阅读/延伸任务、真实结局，以及使用/修订记录。

### 数据与迁移

- 新增案例主记录、不可覆盖的案例版本、版本标签/课程关联、逐项作业/作品、附件、审核记录、使用登记等表；课程、年级、课题、方法/主题标签和作品授权状态可结构化检索，不依赖解析正文。
- 版本编辑采用新建版本；发布新版本后保留旧版本记录及其状态，不物理删除历史版本。
- 发布前按案例类型检查模板必填项：案例标题不超过 20 字；中文摘要 200–300 字、英文摘要 120–180 词；中英文关键词各 3–5 个；教学型正文不少于 10,000 字且配套手册，小微案例正文不超过 4,000 字；合并查重结果需登记。重复率通常不高于 15%，符合院级建设阶段例外时允许至 20%，须记录例外依据。未满足项显示阻断发布的原因，不能静默放行。
- 对 `admins` 做兼容性角色扩展，现有管理员凭据和既有文章数据保持不变。
- 提供幂等、只增不删的数据库迁移；部署前后不重置账号密码、不运行会清空数据的初始化/seed 脚本。迁移失败时应用应明确报错，不得带着缺表继续开放不完整接口。
- 视觉传达案例默认编号前缀 VC，按 `VC-年份-三位流水号` 唯一分配；数据模型保留规范列出的其他专业代码。

## 明确不在首期范围

- 不从知识库批量导入或自动转换现有研究稿、学生作业和公众号内容。
- 不提供学生账号、学生个人作品提交或学生按班级读取“仅课堂使用”材料的门户；该类材料只对教师账号开放，教师负责课堂内使用。
- 不提供匿名评审专家的独立账号/门户；管理员录入匿名专家评审记录与结论。
- 不自动对接查重、学位点培养方案或外部案例中心。
- 不声称案例已正式入库、已获授权或已实施；这些状态由管理员依据可追溯材料逐案维护。

## 验收标准

1. `/section/method` 展示案例库专用首页，含栏目导语、编辑精选、课程—年级—课题浏览、方法/主题标签、最新更新时间和使用说明；精选与全部案例区分；无案例时显示说明明确的空状态，不显示普通种子文章为正式案例。
2. 案例按课程/年级/课题、方法/主题标签以及规范要求的类型、来源、教学方式、难度/学时和关键词筛选；列表、总数、分页和筛选条件一致。
3. 未发布、待审、授权不清或受限案例不通过公开列表、搜索、直接详情 URL、附件 URL 或关联案例 API 泄露。
4. 教师角色能够登录并读取授权的指导手册/附件、创建使用登记；不能调用管理员写接口。管理员仍可管理原有文章，并可新增/修改案例、教师账号和评审记录。
5. 发布修订版本后，旧版本及其引用仍可查；编号不重复；至少两名评审通过后才允许发布。
6. 详情页包含课题任务、逐项展开的作业作品、过程/媒介/作者自述、综合分析与教学启示；教师区列出教学目标与准备、流程、活动、评价和手册，且受服务器权限保护。发布校验符合案例类型与正文模板要求；两年复审提示、使用登记字段与台账模板一致；空列表、筛选无结果、加载失败和无权限状态均有明确反馈。
7. 数据库迁移可在已有部署库重复执行，不更改现有管理员密码或文章数据；案例私有文件不能通过公开静态目录访问。

## 待实施阶段

规格获用户确认后，再编制逐任务实施计划。实现时先做幂等迁移与访问控制，再做管理端录入、公开目录/详情、教师端手册与使用登记，最后做构建和权限/页面验收。实际案例内容仍待逐案核对、授权与录入。
